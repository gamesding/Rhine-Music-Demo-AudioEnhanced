# Sony 原版音效、FTP 与平板触摸

本轮在播放器设置中加入 DSEE AI、DCフェーズリニアライザー、バイナルプロセッサー、多核并行和边算边播。音频来自本地文件或已下载到本机的 FTP 曲目。Windows 的三项效果执行由 Sony 原 ARM 指令转写、编译的 x86-64 C++，使用原模型与原参数；参考路径继续保留原 ARM 执行。

新增底部播放进度与前端原生会话恢复。十秒实际无损音乐的全开／全关及逐项频谱、相位器合成脉冲测量见 [实际输出测量](SONY-AUDIO-MEASUREMENTS.md)；测量与固定原文件哈希、原 ARM 逐位对照共同验证效果确实执行。

## 原版来源与验证边界

- 提供的 Walkman One 包内音频库导出 `DseeHxCustom`，对应 DSX 2.0；仅凭固件介绍或模式名称不足以确认它就是 DSEE AI。
- 实际 AI 核心取自 [Sony 官方 DMP-Z1 1.02 固件](https://www.sony.jp/audio/update/pc_update_dmp-z1.html)，包含 `DseeAi`、DSX 3.0.7、原版 60,000 字节模型和 ICX1291 配置。Sony 对该产品的 [AI 音质说明](https://www.sony.jp/audio/products/DMP-Z1/feature_4.html)也与这个来源对应。该固件只被解包，没有运行更新器或刷写设备。
- 相位器与黑胶处理使用同一官方音频库，版本均为 1.0.0；相位模式参数来自原版初始化代码，黑胶预设由原版 CSV 解析器生成。原数学库及 C++ 运行库涉及的执行代码一并转写，数据布局与原参数保留。
- 九个运行文件的 SHA-256 固定在 [assets.json](../scripts/sony-walkman/assets.json)，原文件按用户要求放入本私有源码的 `vendor/sony-walkman/`。启动会校验并实际初始化、调用三个效果。Windows 独立 EXE 自带原生解码器和 Unicorn，不需要系统 FFmpeg；源码的其他平台仍可使用 FFmpeg／FFprobe 路径。
- 原 Walkman One 包的外层校验通过，但其 system 分区声明的 MD5 与解包结果不一致：声明 `1d0045ebc5f38926d6ea27ec7a85c860`，实际 `97b27f870f6320b37137060a4d36cfa4`。官方 DMP-Z1 包的外层及 system 分区校验通过。研究副本保留这些记录，未掩盖差异。

**原版算法已经运行，不等于已证明整台 Walkman 的输出完全一致。** 这是解码后的浮点 PCM 桥接，原版 AI 接收 PCM 编码标识；不是复刻 Walkman 的所有解码器、处理路由、音量控制、S-Master 放大器或 DAC。串接次序为 AI → 相位器 → 黑胶，尚无实机完整链路的逐样本对照。

相位器串扰已修复。原双声道包装入口把 L、R 交错数据送进同一组历史，另一声道曾出现约 `0.000061–0.000202` 的峰值。桥接现在为左右声道分别初始化原上下文，分别调用原转换函数与原滤波内核，然后按原位模式交错回双声道。系数和滤波运算保持原版。六种模式、四种采样率的双向串扰均为零；每个声道与原版连续单声道入口逐位一致，非整块输入、声道互换与 OFF 也通过。[24 组详细结果](SONY-PHASE-VERIFICATION.json)保留原串扰复现和修复证据。设置显示实际声道隔离自检结果。

## 本地准备

Sony 二进制、模型和原版预设已按用户要求纳入本私有源码副本，不属于项目 MIT 授权。Windows 直接使用独立 EXE。其他平台源码开发需要 Python／Unicorn 及 FFmpeg，也可从研究副本的 `runtime-assets` 重新校验安装：

```sh
python3 -m venv .tools/walkman/venv
.tools/walkman/venv/bin/python -m pip install -r scripts/sony-walkman/requirements.txt
node scripts/prepare-walkman-assets.mjs --from "/path/to/private-research/runtime-assets"
export SONY_WALKMAN_PYTHON="$PWD/.tools/walkman/venv/bin/python"
npm ci
npm run build
npm run music -- --port 5175
```

还需本机 FFmpeg / FFprobe，默认从 PATH 查找。可以用 `SONY_WALKMAN_FFMPEG`、`SONY_WALKMAN_FFPROBE` 指定可执行文件，用 `SONY_WALKMAN_ASSETS` 指定私有运行文件目录。安装或更换组件后重启音乐服务，再打开设置检查组件状态。本轮已在开发主机实际运行，尚未在 macOS / iPad 硬件上完成验证。

DSEE AI 原版接受 44.1／48 kHz 单声道或双声道 PCM 输入，输出 176.4／192 kHz 浮点 WAV；相位器与黑胶原版接受 44.1、48、176.4、192 kHz，保留输入采样率。176.4／192 kHz 音源自动旁路 DSEE，继续应用已开启的相位／黑胶；其他未验证的采样率逐项旁路不支持的效果。设置显示原因，技术标志依据实际处理链。不会为了使用 DSEE 而偷偷降低高采样率音源。单声道转换为双声道；多声道不能应用当前桥接。

ALAC 使用原 [ALACSpecificConfig](https://github.com/macosforge/alac/blob/master/ALACMagicCookieDescription.txt) 的 32 位采样率与真实位深，解决 MP4 通用采样描述中 16 bit／1 Hz 造成的错误显示。旧本地索引自动重读；FTP 已缓存曲目再次读取时升级元数据。Windows JSON 管道使用 UTF-8／ASCII 转义保留中文错误，不再把不支持的采样率误报成缺少 Python／Unicorn。原生 PCM 管道遇到写入背压会等待空间，并保留全部样本。

DSD 转 PCM 路由先转换为 44.1 kHz，随后可使用三项音效；原生 DSD 与 DoP 完全旁路音效。单曲最长一小时，音效输出上限 2 GB。WASAPI 共享输出可由系统重采样；ASIO 要求设备接受精确采样率。

## 多核与边算边播

默认启用多核及边算边播，音效本身默认 OFF。每项原版效果保留一个连续状态，多项同时启用时最多使用三个工作进程；双核设备将两个阶段合并。不会分割成互不相关的音频片段来破坏滤波器、神经网络或黑胶状态。单项效果通常只需要一个处理进程，不能保证占满所有 CPU 核心。

先前 ARM 桥接的性能和等待记录作为历史证据保留。当前 C++ 路径在真实 ALAC 十秒片段上，三效果串行处理约 3.31 秒，原 ARM 路径为 18.22 秒；音频和内部状态逐位一致。不同 CPU、歌曲与界面负载的速度会变化。[本轮验证记录](UI-REVIEW-V0.3.0.md)区分历史版本与本次修正。

Windows 首次播放通过原生解码管道立即供应 PCM，不再先完整解码整首或生成解码中间文件。约 0.5 秒音频缓冲后播放，等待不随整首时长扩大。切换音效从当前播放位置解码、运算，并恢复完整歌曲时间轴；旧读取结束后立即取消过时任务。暂停后切换再恢复，以及向片段起点之前拖动，也会正确准备对应位置。浏览器兼容参考路径仍保留完整解码以确定长度的做法；Windows 推荐 WASAPI／ASIO 原生输出。

当前二十秒合成双声道校准音频，三进程约 0.89 秒开始原生播放、约 3.31 秒完成；最终 3,528,000 帧均为有限值，串行 ARM 与并行 C++ 的 PCM 哈希相同。五分钟合成曲目从第 180.123 秒起算，首缓冲约 0.59 秒，随后切换三个音效预设约 0.67 秒，旧任务取消、完整时间轴及未完成就播放均通过。原生设备回调不等待未生成的数据；若 CPU 不能持续跟上会显示缓冲状态。关闭“边算边播”仍等待整首完成。

并行与串行使用相同顺序和状态，已比较输出 PCM 哈希。已完成的输出缓存可以复用；更改效果会准备新音源并恢复原来的位置与暂停状态。准备失败会显示错误，不会绕过 Sony 效果播放原文件。全部 OFF 时直接使用曲目原来的音源，包括 FTP 音源。

切换或取消尚未接入播放的准备请求，会取消对应的过时任务并退出其工作进程。已经开始边算边播的歌曲暂停后可以继续完成缓存。设置可停止播放并清理已完成的音效缓存；仍在处理时会提示稍后重试。缓存和临时解码文件位于本机数据目录，不会写回原曲目。

## 标志与动画

正在播放或暂停的当前专辑中，只显示已接入当前音源的音效标志；准备阶段、错误、停止及 OFF 不显示。DSEE 使用 `art/DSEE_LOGO.avif`，相位器按用户要求使用 `art/S-MASTER.webp` 的主标志，黑胶使用 `art/vinyl.png`。通过 [生成脚本](../art/build_audio_tech_logos.py)描成透明 SVG，保留轮廓，避免白底；没有把 S-Master 硬件放大器描述当成软件能力。

标志颜色跟随暖昼 / 深夜。进入和扫光采用线性动画，黑胶每 48 秒匀速旋转一圈；暂停时停转，减少动态效果时静止。原始素材和 Sony 标志的权利归原权利人，不因转换为 SVG 而变成 MIT。

## FTP 与平板

设置中的 FTP 音乐库可填写主机、端口、用户名、密码、绝对音乐目录及 FTP / FTPS 加密方式。先测试，再保存并扫描。扫描只读取目录，不下载整库；歌曲按文件夹归并，曲名先取文件名。选择歌曲后从完整下载的本机缓存读取原采样率、位深、无损参数、标题、歌手、专辑、曲号／碟号及内嵌封面；DSF 包括 ID3 标签。已识别信息在重扫与重启后保留，界面更新不重启歌曲，缺少标签时保留文件名。索引中的所选歌曲完整下载到本机后播放，支持 HTTP Range 和 Sony 音效。Hi-Res 标志依据这些原音源参数，详见 [音源标识与金边](HI-RES.md)。FTPS 校验证书，传输使用被动模式；不支持 SFTP，不改写远端文件或标签。

密码只保存在本机数据目录 `ftp-library/connection.json`（macOS 文件权限 0600），不写入浏览器偏好或状态响应。FTP 缓存单曲上限 1 GB、总容量上限 4 GB，设置提供清理缓存；没有对远端文件执行写入或删除。

触摸以平板横竖屏为重点：播放、设置、返回、曲目、导航及表单保持至少 44px 触摸区域，歌单和设置面板可滑动，专辑滑尺支持手指轻点和水平滑动，保留原有封面拖动。测试使用触摸模拟；并不等同于已经验证 iPad Safari、外接音频设备或真实手势的所有兼容性。

音乐服务继续只监听 127.0.0.1。触摸适配不包含让另一台 iPad 经局域网访问电脑的部署方案，也没有放宽 Origin / Host 校验。

## ARM 转 C++

完整支持的三效果链路已转写为 x86-64 C++，包含 32,159 个指令位置、65 个按地址划分的编译代码页。原地址、指令字节、模型、系数、运算顺序、整数与浮点位模式保留。运行时直接执行已编译代码，未知地址或无效访问明确失败，不退回 ARM 模拟器。源码、指令元数据及生成器均纳入本私有源码，并复制到固件研究目录。[构建及研究说明](../native/sony/README.md)提供具体命令。

246 组完整链路与原 ARM 对照，5,046,272 个输出值和所有已分配处理状态逐位一致；覆盖支持的采样率、全部音效组合、不同分块、静音、单声道脉冲、噪声及微小幅度信号。[详细对照](SONY-X86-VERIFICATION.json)保留参数、耗时、哈希及结果。真实 ALAC 片段另通过逐位比较。此前局部 CReLU 的 36 组／8,912 个特殊浮点值对照保留为历史研究证明；完整软件算法对照不代表 Walkman DAC、S-Master 硬件及整套固件均已复刻。

## Windows 原生输出与 DSD

独立窗口用 Electron 保留既有 Three.js 界面；歌曲音频由独立 C++ 进程解码并输出，未送入 HTMLAudio 或 Web Audio。默认原生 WASAPI，设置可选择厂家 ASIO 驱动与输出声道。原生播放禁用浏览器氛围音乐和界面音效，避免混入数字直出。ASIO 驱动仍需由设备厂家提供；程序包含 ASIO 主机而不安装声卡驱动。

设置提供 DSD 转 PCM、原生 DSD、DoP。后两者仅经 ASIO，锁定数字音量为 1，禁用淡入淡出、Sony 音效、混音和重采样；**DoP 是 DSD 的封装，不会因此允许 PCM 音效**。设备不支持所选采样率／DSD 模式时明确报错，不会改为另一种输出。DSF 与未压缩 DFF 已接入，DST 压缩 DFF 未支持。

自动化检查已实际调用固定哈希的原生 DLL：DSF／DFF 的 DSD64、128、256 位序、声道、去块填充后的全部原始字节一致；DoP 的交替 0x05／0xFA 标记、双声道和全部载荷一致；转换 PCM 有限值。真实 WASAPI 静音样本通过播放、暂停、跳转、自然结束和停止。当前尚无 ASIO 驱动／DAC，因此无法宣称硬件 DSD 直出、厂商兼容性、热拔插或长期无故障已验证。

扩大块边界测试发现 BASSDSD 2.4.2 在 DSF 样本字节数整除 4096 时漏读最后完整块。C++ 主机为 DSF 提供只读、可寻址的 DSDIFF 容器视图，缓存最多两个 4096 字节声道块；仅按规范重排位序与容器，不处理、复制或改写音乐。4098、8192、32768 字节／声道、三倍率、DSF／DFF 共 18 组合的完整 raw 与 DoP 载荷均通过，包含此前漏块条件。

DSF 的尾部 ID3v2.3／v2.4 支持中文标题、歌手、专辑及专辑歌手、曲号／碟号和内嵌封面；真实格式夹具通过本地扫描、索引重载和封面 HTTP 字节比较。音频视图限定读取声明的 DSD 数据，不把标签送入音频处理。附加两种标签后的完整原始 DSD 和 DoP 与无标签文件逐字节相同，读取后源文件不变。格式依据 [Sony DSF 1.01 规范](https://dsd-guide.com/sites/default/files/white-papers/DSFFileFormatSpec_E.pdf)，没有添加改写标签的功能。
